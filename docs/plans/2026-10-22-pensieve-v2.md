# Pensieve v2: the engine under the new design

Plan of 2026-10-22. Design: [`docs/design/pensieve.html`](../design/pensieve.html) (v3,
"a basin of memories"). This plan builds what every screen of that design needs: the data
model, the server pipeline, the API and MCP, and the Mac core (capture, compression, the
iCloud copy, dictation). The SwiftUI screens themselves wait for the UI work; views only
change where they must to keep compiling.

## Scope

- Four kinds of recording: `call` (microphone plus Mac audio, today's), `video` (webcam
  plus microphone, interviews), `screen` (screen plus Mac audio, optional microphone),
  `dictation` (microphone only, hold Option+Space anywhere, pasted at the cursor).
- Marks ("Markeer moment"): seconds from the start plus an optional note.
- Labels: free text per person, no colours; filter by kind and by labels (OR).
- Transcripts with segments (start, end, speaker, text) and subtitles (`.srt`).
- Notes per kind: calls keep the meeting notes; video gets core, quotes and chapters;
  screen gets steps; dictation none.
- Video and screen are compressed on the Mac; only their audio goes to the server, and
  only when the person asks for a transcript.
- "Verklein video" for any video file, with three qualities and an optional size limit.
- The iCloud copy with lowercase names, audio always, the new file names, subtitles,
  Finder tags, dictations together, and the move from today's names.

## Data model (server)

`recordings` gains:

| Column | Meaning |
|---|---|
| `kind` | `call`, `video`, `screen`, `dictation`; existing rows become `call` |
| `transcribe` | whether the pipeline transcribes after compressing; false leaves the recording `stored` until the person asks |
| `segments` | JSON `[{start, end, speaker, text}]`, seconds from the start; the plain `transcript` stays for search |
| `marks` | JSON `[{at, note}]` |

`notes` becomes a union on `type`: `meeting` (today's shape; old rows without `type` read
as meeting), `interview` (summary, quotes with `at` and speaker, chapters with `at`),
`steps` (summary, steps with `at`).

New tables: `pensieve_labels` (id, person, name; unique per person, case-insensitive) and
`recording_labels` (recording, label). A label belongs to one person; a person can label
any recording they can see (their own or shared with them), and only sees their own
labels. Filtering by label is by name, so it works the same over own and shared
recordings.

New status `stored`: compressed, waiting for a transcript the person asks for.

## API

- `GET /pensieve/recordings?scope&q&kind&label=a&label=b`: labels OR-combined, kind
  exact; `q` also matches the person's label names and mark notes.
- `POST /pensieve/recordings` takes `kind`, `marks`, `labels`, `transcribe`.
- `POST /pensieve/recordings/:id/transcribe`: the owner asks for the transcript of a
  `stored` recording.
- `PUT /pensieve/recordings/:id/labels {labels: [names]}`: the person's own labels on a
  recording they can see; unknown names are created.
- `PUT /pensieve/recordings/:id/marks {marks}`: owner only.
- `GET /pensieve/recordings/:id/subtitles`: SRT from the segments.
- `GET|POST /pensieve/labels`, `PATCH|DELETE /pensieve/labels/:id`.
- MCP: `list_recordings` and `search_recordings` take `kind` and `labels`;
  `list_recording_labels` (read) and `label_recording` (organize). No tool starts,
  transcribes, shares or deletes.

## Transcription

OpenAI (checked against the docs of 2026-10-22): only `whisper-1` (`verbose_json`) and
`gpt-4o-transcribe-diarize` (`diarized_json`) return timestamps; `gpt-4o-transcribe` and
`gpt-transcribe` return text only, and `timestamp_granularities` is whisper-only. So:

- A recording that needs timestamps (video and screen for subtitles, or any recording
  with `pensieve.speakers` on) goes to the diarizing model with `chunking_strategy:
  auto`; without speakers the labels are dropped from segments and text.
- A call without speakers and a dictation keep `gpt-4o-transcribe` text, no segments.
- Parts stay 20 minutes; `Audio.split` returns each part with its start (measured with
  ffprobe, so a cut on a packet boundary does not drift) and segments are shifted by it.

Notes per kind run through the existing `pensieve.notes` agent kind with one skill per
kind: `meeting-notes`, `interview-notes`, `screen-steps`. Their prompts get the
transcript with `[mm:ss]` stamps when segments exist, and the marks. Dictation skips
notes; a dictation called "Dictaat" takes its first words as title. Compressing and
transcribing a dictation run at priority `urgent`, as someone waits to paste.

## Mac core (no UI)

- **Capture.** `VideoCapture` (AVCaptureSession, camera plus microphone, to a `.mov`)
  and `ScreenCapture` (ScreenCaptureKit with `SCRecordingOutput`, system audio, optional
  microphone; macOS 15). The call recorder stays. Every recorder reports `elapsed`, which
  stamps marks.
- **Compression.** `VideoProfile` (480p, 720p, 1080p, 1080p high) with bitrates that give
  the design's sizes (3.4, 6.9, 13.8 MB per minute); recording presets small 720p, normal
  1080p, high. `AssetWriterEncoder` writes H.264 MP4 with the hardware encoder.
  `AudioExtractor` mixes every audio track to `audio.m4a`.
- **Shrink** ("Verklein video"): estimates per quality, never upscales, says so when the
  source is already small enough; with a limit targets 95 %, verifies the output and
  re-encodes lower when it overshoots. Output `<slug>-<height>p.mp4` next to the original.
- **Outbox and shelf.** A pending upload carries kind, marks, labels and whether to
  transcribe. For video and screen the outbox sends `audio.m4a` while the shelf keeps the
  raw original and, once compressed, the MP4, bound to the recording id the server gave.
- **iCloud copy.** Folder `yyyy-MM-dd_<slug>` (lowercase, accents folded), files
  `<slug>.mp4`, `audio.m4a`, `samenvatting.md`, `transcript.md`, `ondertitels.srt`,
  `.pensieve.json`; dictations in `dictaten/` as `<date>_<slug>.md` and `.m4a`. Labels
  become Finder tags. A folder from the old copy is renamed in place (`notulen.md` →
  `samenvatting.md`, `transcript.txt` → `transcript.md`); new files are written before
  old ones go. The original video is deleted only after the MP4 in the folder plays
  (duration matches) and iCloud reports it uploaded.
- **Dictation.** `HoldHotKey` (Carbon hot key, pressed and released, no Accessibility
  needed), `DictationRecorder` (AAC to m4a), the transcribe call (upload as kind
  `dictation`, wait for the transcript) and `Paster` (insert through the Accessibility
  API into the focused field, else Command-V, else leave it on the clipboard).

## Deferred to the UI work

The gallery, the memory view (timeline, lyrics transcript, side panel), the recording
stage and pill, the floating orb, the dictation HUD, the shrink sheet, the label filter
menu and Settings › Labels and the Mac-side settings (format of video, size cap,
automatic transcription per kind). Pause during a recording. Calendar defaults for the
title (needs the calendars plan); until then the title and labels come from the previous
recording of the kind.

## Open questions

- May a bot suggest a label afterwards, for example from the calendar? (From the design;
  not built.)
- Speaker letters restart per 20-minute part: "A" in part two need not be "A" in part one.
  The diarizing model accepts known-speaker samples; feeding it clips from part one would
  fix that. Not built.
- `gpt-4o-transcribe-diarize` and `gpt-4o-transcribe` shut down on 2027-02-26 and
  `gpt-transcribe` returns no timestamps. Before then: a successor with timestamps, or a
  local aligner.
- Should a video or screen recording that never got a transcript get the title-based
  notes at all? Default: no notes without a transcript.
- With the iCloud copy switched off, video and screen still go to `iCloud Drive/Pensieve`:
  it is their only home, since video never reaches the server.
- The app a dictation was pasted into ("geplakt in Mail") is not stored yet.
- Mac-side settings (video format, maximum per file, automatic transcription per kind)
  are local defaults until the UI decides where they live.
