# Lumos: films and series to watch together

Plan of 2026-10-25, condensed from the private handoff (`media/docs/lumos-implementation-handoff.md`
in the operator's `tv` repository, which also holds the background research and the media
stack). Lumos is a native Mac app and a Burrow module that help the two people of the
household choose what to watch together. The media stack on Dobby (Seerr, Radarr, Sonarr,
Prowlarr, qBittorrent, Jellyfin, Bazarr) stays the backend; Burrow never rebuilds it.

## Design

The visual and interaction reference is the private desktop study
`/Users/gideon/git/tv/design/media/desktop/` (`index.html`, `README.md`, `src/`). It is
referenced by path, not copied: it holds real first names and artwork whose redistribution
is not cleared. Take from it:

- A fixed Mac window: sidebar (Ontdekken, Onze lijst, Films, Series, Klaar in Jellyfin,
  Smaak, Overgeslagen), a compact toolbar (title, Samen or your own scope, search), image
  rows visible at once, an inspector of about 404 pt on the right. No website header, no
  hero, no web view app. Only the rows and the inspector scroll.
- Wide stills for the proposal rows, poster rows for lists and the library.
- The inspector: trailer or stills, facts, synopsis, genre and trait labels, scores per
  source with votes, short reviews, "more/less like this", similar titles, makers.
- Keyboard: arrows over cards and rows; Enter opens the inspector with focus inside;
  Space toggles it without moving focus; Esc stops the trailer, then closes the
  inspector and returns focus to the card; `J` list, `N` not now (reason optional),
  `T` trailer, `Z`/⌘Z undo, ⌘F and `/` search.

## Decisions

- **Mac only**, mouse and keyboard. No iOS scope.
- **No time-limit filter** and no hidden runtime filter; runtime is metadata.
- **Yes** puts a title on the list of the current scope (Samen: the household's list;
  your own: your personal list). **No** is "not now" with an optional reason; "already
  seen" is its own verdict and never counts as dislike. Every change can be undone.
- **Personal lists are private**, like a Pensieve recording: the other person never
  sees them, not in rows or details either. The household's list is everyone's, like
  outings. So the prototype's "Eén van jullie wil dit" row became "Op jouw lijst, nog
  niet samen", showing only your own entries.
- **Undo on the server**: every change answers with a `changeId`; undoing it reverses
  exactly what it did, also a "yes" that cleared an earlier "not now". Only its author can
  undo it. Rows are never deleted, only marked removed or undone.
- **Fixtures are isolated**: `LUMOS_CATALOGUE=fixture` serves invented titles plus three
  real ones with checked trailers; every catalogue answer says `dataOrigin: 'fixture'`,
  the app shows "Testgegevens", list rows carry their origin so fixture entries never
  appear next to the real catalogue, and the server refuses fixtures next to
  `LUMOS_SEERR_URL`, behind Cloudflare Access or on a public address.
- **Keys stay on the server**. The Mac talks only to `/api/lumos/*`; later Seerr and
  TMDB keys come from config, never reach a client, and responses are mapped to Lumos
  contracts, never proxied.
- **Trailers stream after a click**, compact in the inspector, nothing stored: YouTube in
  a small `WKWebView` through its IFrame API with the server as origin, direct streams in
  `AVPlayerView`. "Playing" only from the player's own event. Stopped on Esc, close and
  title change. A source link opens it large; no resolution is promised.
- **Scores and match apart**: scores per source with scale, votes and date, absent when
  the source has none; "why proposed" is its own section.
- **History import** later, as an operator-agent skill (export or API first, computer
  use as fallback), no Trakt or other aggregator.

## Phases

0. **Plan and names** (this file, `naming.md`, the wiki). Done.
1. **Skeleton with fixtures** (local): `modules/lumos`, contracts, `apps/lumos-mac` with
   rows, inspector, keyboard, undo, trailer spike. Done on `feat/lumos`.
2. **Own data**: shared and personal lists, verdicts, undo, persisted. Done on
   `feat/lumos`; nothing is requested anywhere.
3. **Live catalogue**: a Seerr provider. Seerr serves TMDB's metadata, artwork, trailer
   references and RT/IMDb ratings, so no TMDB key is needed. One Seerr service key for the
   household; requests are not attributed per person. Done and deployed 25 October.
4. **Requests**: an outbox (`lumos_requests`) written with the list entry, at most one
   Seerr request per title after a 15 s undo window, retries with backoff, never
   cancelling or deleting. Series ask the first season unless seasons are chosen. Done
   and deployed 25 October.
5. **Watch**: the title's page in Jellyfin's web app for this machine, and a start on
   the TV through an active Jellyfin session, confirmed by the session's own
   `NowPlayingItem`. Built 26 October against a fake Jellyfin; live once the operator
   runs `connect-lumos-jellyfin.sh` in the `tv` repository and the real TV test is done.
6. **History import**: tables, run API, the skill ported from `tv`.
7. **Editorial and taste**: curated snippets, together-first ranking.
8. **A second face, undone** (26 October): a playful face was built as `apps/hogsmeade-mac`
   on the same model and removed the same day, because Hogsmeade is the outings app, not
   a second Lumos (commit `c996206` still has it). `LumosCore` and `LumosUI`, the image
   cache, the disk snapshot and the season menu stayed.
9. **Pages, shelves and the Zoeker** (27 October): a title as a page over the rows with a
   prefetched cache instead of the drawer; people with their work; Films and Series as
   the shop's shelves through Seerr's discover; the Zoeker; budget, revenue, cast,
   makers and seasons in the details; TMDB's related titles. Done.

## Boundaries

Phases 3 to 5 are approved and deployed. Lumos talks to Jellyfin only to find a title,
list sessions and start playback on a screen the person chose; it never deletes, marks
or reads user data. Until their own approval: no account logins or history imports, no
scheduled tasks. Fixtures never run on Dobby; the config refuses them there.
