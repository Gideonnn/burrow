Mail · ontwerp v2

Verwerkt: een overzicht als hoofdscherm, Werk als werkaccount, per account een eigen inbox, de eigen API per provider, geen T3 en meteen native SwiftUI. De agent doet zijn werk op de server: wat hij filtert, is ook op je telefoon gelezen en weg uit de inbox. In de app controleer je daarna kort wat hij filterde. Het venster is klikbaar; v1 staat nog in v1.html.

Wat de agent op de server doet

Alles gebeurt bij de provider zelf, dus je telefoon ziet hetzelfde als de app. Terugzetten draait elke stap om.

Agent besluit Gmail (Gmail API) Outlook en Werk (Microsoft Graph) Fastmail (JMAP) Op je telefoon
Spam, phishing, acquisitie Label SPAM, gelezen Naar Ongewenste e-mail, gelezen Naar Junk, $seen Weg uit de inbox. De spamfilter van de provider leert mee.
Ruis: nieuwsbrief, melding, CC zonder vraag INBOX-label eraf, gelezen Naar Archief, gelezen Naar Archive, $seen Weg uit de inbox. De kern komt in "Ter info" in het overzicht.
Antwoord nodig Ster Vlag $flagged Vlag of ster in iOS Mail en Gmail
Bon, factuur, bezorging Label "Bon" enzovoort Categorie Keyword Blijft in de inbox (zie keuze 3)
Terugzetten Vorige map of labels terug, weer ongelezen, en een geleerde regel voor die afzender Staat weer in de inbox

Hoe het in elkaar zit

Eén SwiftUI-app plus een kleine achtergrondhelper (een login item, start mee met de Mac). De helper werkt ook met het venster dicht, zodat je telefoon rustig blijft.

Gmail API ───── Pub/Sub-pull of history-polling ──┐ Microsoft Graph delta-polling elke 30 s ─────────┼──▶ Mail-helper (login item, Swift) (Outlook + Werk) │ · sync naar SQLite Fastmail JMAP ── push via EventSource ────────────┘ · triage: claude -p --model haiku (Codex als uitwijk) · acties terug naar de provider (gelezen, spam, archief, vlag) · volgt verstuurde mail: wacht er nog iemand op een antwoord? · MCP-server op localhost:4717 ◀── Claude Code en Codex │ Mail.app (SwiftUI) ◀──────────┘ leest dezelfde database Microsoft-webhooks hebben een publiek adres nodig; daarom polling. Gmail Pub/Sub-pull werkt zonder publiek adres.

Wat erin zit en wat niet

Wel

  • Overzicht als startscherm: wat moet ik doen, waar wacht ik op, wat is er weggefilterd
  • Per account een eigen inbox (Gmail, Outlook, Fastmail, Werk)
  • Lezen, beantwoorden, doorsturen, archiveren, verwijderen, concepten, bijlagen
  • Opvolgen: de agent ziet welke van jouw vragen onbeantwoord blijven en stelt een herinnering op
  • Gefilterd als controlelijst: per mail klopt of terugzetten, of alles in één keer
  • Zoeken in gewone taal, ook via je agents

Niet

  • T3-koppeling: alleen MCP
  • Gezamenlijke inbox (het overzicht vervangt die)
  • Regels bouwen, vlaggen en mappen in de app (de vlag op de server is van de agent)
  • Snoozen, opmaakbalk, agenda, contacten, sjablonen, gepland versturen, plug-ins
  • Agent die verwijdert of verstuurt
