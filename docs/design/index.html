Mail · ontwerp v4

Nieuw: een takenlijst met runners. Een taak, zoals "factuur verwerken", komt in een wachtlijst op de server en wordt opgepakt door een runner: de server in de meterkast, of de Mac-app zodra je die opent. Net als bij T3 Code draait de agent op de machine die de taak uitvoert, met de Claude Code of Codex die daar is ingelogd. Taaktypes zijn losse vaardigheden, zodat er later gezinstaken bij kunnen. Probeer tab 5: de app is net geopend en er staan taken klaar. Eerdere versies: v1.html tot en met v3.html.

Taken en runners

De server bewaart de takenlijst. Runners melden zich aan met hun API-sleutel en pakken alleen taken die bij die sleutel horen. Een taaktype zegt waar het mag draaien.

Factuur verwerken, stap voor stap

  1. De triage op de server ziet een factuur en zet de taak klaar voor je Mac.
  2. Opent de app, dan pakt de runner op je Mac de taak op en leest de pdf uit: leverancier, nummer, datums, bedragen, btw, IBAN, categorie.
  3. De runner vergelijkt met eerdere facturen van dezelfde leverancier: bedrag ongewoon hoog? IBAN anders? Dan een rode waarschuwing.
  4. Je ziet een voorstel met stappen om aan te vinken: pdf opslaan, boeken, mail archiveren, betaling klaarzetten.
  5. Na "Goedkeuren" voert de runner de stappen uit. Betalen doet hij nooit; hooguit zet hij een betaling klaar die je in de bank-app goedkeurt.

Later: taken voor het gezin

  • Een taaktype is een map met instructies, tools en een paar instellingen (aanleiding, waar, wie, goedkeuring), zoals een Claude-skill. Een nieuwe taak toevoegen is geen app-update.
  • Voorbeelden: schoolmail naar de gezinsagenda, pakketten volgen, abonnementen en verzekeringen bijhouden, een boodschappenlijst uit een recept.
  • Een "Gezin"-persoon met eigen mailboxen en taken, die Gideon en Eva allebei zien.
  • Andere aanleidingen dan mail: een tijdstip, een agenda-item, een vraag in de app.
